# secrets — APIキーを GitHub 経由で安全に受け渡す場所

⛔ **このフォルダに `.env` やキーの値をそのまま置かない。** 置いてよいのは次の2つだけです。

| ファイル | 中身 | GitHub に上げてよいか |
|---|---|---|
| `recipient_pubkey.pem` | 錠前（公開鍵）。閉じることしかできない | ✅ よい（見られても困らない） |
| `gemini_keys.sealed.json` | 錠前で閉じた箱。Gemini のキーの行だけが入っている | ✅ よい（鍵が無いと誰も読めない） |

- 箱を開ける**鍵（秘密鍵）は、クラウドの作業環境の中だけ**にあります。GitHub にもチャットにも出しません。
- 使い終わったら、作業環境の鍵を消します。⇒ GitHub に残った箱は、二度と開けられなくなります。
- 作業環境は、しばらく使わないと片付けられます。そのときは鍵も消えるので、錠前を作り直して、箱も作り直します。

## PC でやること（3つ）
```bat
cd （このリポジトリを置いた場所）
git pull
pip install cryptography
python tools\keybox.py seal
```
1. 画面に出る **「錠前の指紋」が、チャットで伝えた指紋と同じか**を確かめる（違えば止めて、知らせる）。
2. 「閉じたキー：N 個（変数名：…）」が、使いたいキーだけになっているか確かめる（値は出ません）。
3. 箱を GitHub に上げる：
   ```bat
   git add secrets\gemini_keys.sealed.json
   git commit -m "キーの箱"
   git push
   ```

- `.env` の場所が違うときは `--env パス`、特定の変数だけにしたいときは `--key-name 変数名`（複数可）。
- 閉じるのは、名前に GEMINI か GOOGLE と KEY を含む変数だけです（それ以外の行は入れません）。

## 確かめたこと（2026-10-12、偽のキーで試験：14 / 14 合格）
閉じられる・開けられる・開けた中身が元と同じ／箱の中にも画面にもキーの値が出ない／キー以外の行は入れない／
違う鍵では開かない／中身を1ビット書き換えると開かない／鍵と開けた中身はリポジトリの中に置けない／
鍵と開けた中身は自分だけが読める（600）。
