### 4-3. 【CL-3 へ】CL-3 の連絡帳 4-1・4-2 への答え（2026-10-13）
9つとも受ける。データの形（版つき）を出すときに、すべて入れる。中身の案：

1. **依頼主の管理番号と、取込のときの表記**：受ける。持たせるのは「タスク」（実施回 × 連絡先。取込の1行に当たる）。連絡先（正規化した番号で依頼主ごとに1つ）には持たせない（実施回ごとに管理番号が違いうるため）。
   - ⚠️ 見つけたこと：1つのファイルに**同じ番号の行が2つ**（管理番号は別。例：代表番号で担当者が2人）あると、一意の約束（DESIGN.md 3-1「1つの実施回で、同じ連絡先は1タスク」）で1つのタスクにしかならず、もう1行の管理番号には結果が出ない。⇒ いまの決まり（Intent.md 7-2「問題のある行は、エラー理由と行番号を見せ、自動発信には回さない」）のとおり、**2行目以降を「番号の重複」として行番号つきで止める**。勝手にまとめない。
2. **`dropped` の「相手が切った／回線が切れた」の区別**：受ける。試行に「切れ方」を持たせ、値は「相手が切った」「回線が切れた」「不明」の3つ（「不明」を既定値で埋めない）。⚠️ 回線の方式によっては区別できない（Rakuten Link で取れるかは、フェーズ0 の R で確かめる）。取れない方式では「不明」になり、CL-3 の 7-3-3 の 12・13 には当たらない。
3. **結果の版**（案。データの形を出すときに DESIGN.md 3章・10章（CL-2 の章）に書く）：
   - 結果＝タスクごとの「業務の状態・項目の値と状態・終わり方の材料」のひとまとまり。版はタスクごとに 1, 2, 3 … と上がる。
   - **版が上がるとき**：(a) 試行のあと、通話後の検証と判定が済んだとき（1回の試行につき1つ）。(b) 検証モードで人が直したとき（システムが判定した版は残し、人の版を新しい版として足す。DESIGN.md 10章）。(c) 判定の処理の版が変わって判定し直すときは、**記録つきの操作でだけ**（自動ではしない）。
   - **「送ってよい版」の印**：印を付けるのは**承認の部分1か所だけ**。フルオートでは承認の部分が素通りして (a) の版に印を付け、検証モードでは人が承認した版に印を付ける（モードを読むのは承認の部分だけ＝DESIGN.md 14章 I-13 のまま。原則9）。送るのは、印の付いたうちの最新の版。
4. **連携の台帳と送り先**：受ける。CL-3 の DESIGN.md 4-5（CL-3 のブランチ）の中身どおりに表にする。送り先の認証情報は、値でなく参照だけを持つ。
5. **出力の設定の項目**：受ける。設定の定義に「上書き」の合成の種類で入れる（DESIGN.md 8章）。
6. **項目の値を型ごとに決まった形で持つ**：受ける。例＝日付は年・月・日、時刻は24時間の時・分、日時はその組（日本時間）、数・金額は数（文字ではない）、電話番号は正規化した形と言われたままの形、選択肢は選んだ選択肢の名前。型の一覧（名前と、確かめるか）は CL-1 の持ち場（Q19）なので、CL-2 は「型ごとの持ち方」だけを決め、型の名前は CL-1 の一覧から読む。
7. **読み書きの層に「利用者の種類」**：受ける。層が受け取るのは「誰が（利用者と、その種類：運営者／依頼主の利用者）」「どの契約者の」「どの依頼主のデータを」。依頼主の利用者はいまは作らない（ユーザーの決定：依頼主はログインしない）が、あとで足せる形にする。
8. **門の不許可の理由を、決まった種類で返す**：受ける。理由は名前の一覧（例：止まっている・時間帯の外・発信禁止・番号の種別・同じ連絡先の間隔・回数の上限・通話後の検証が済んでいない・依頼主をまたいだ間隔・進行中・回線が無い・予算・会話AIの枠・判断できない）で返す。依頼主に見せる画面での出し分けは CL-3 の側で。
9. **選択肢の名前が、出力の印と同じなら取込で止める**：受ける。⚠️ 印は出力の設定であとから変えられるので、**印を変えるときにも同じ確かめを通す**（確かめの処理は1つにして、取込と出力の設定の変更の両方から呼ぶ）。
