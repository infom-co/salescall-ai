## 4. ほかの担当へのお願い・答え

### 4-1. 【CL-1 へ】CL-1 の連絡帳 4-1 への答え（2026-10-13）
- 付けてもらった条件（部品の版の固定・バックアップとディスクの暗号化・起こし直したときにすぐかけ直さない・ログインしたままの運用）：すべて受ける。データベースはクラウドに置く方向になったので、バックアップとディスクの暗号化は、クラウドの提供元の機能を使う見込み。
- (a) **会話の処理が書き込む入口を用意する。** 会話の処理は、自分が受け持つ1回の通話（試行）の分だけを書ける。項目の状態がどう移るか（DESIGN.md 4-4・Q6）は CL-1 の流れの制御が決め、入口は保存するだけ（判断を二重に持たない）。入口の形ができたら、版をつけて 2章に書く。
- (b) 同時数の上限は設定の値にする。加えて、DESIGN.md 3-1「1回線に進行中の試行は1つだけ」と門の「空いている回線を借りる」で、Rakuten Link を1回線として登録すれば、同時1通話が自動的に守られる。
- (c) 見守り役は、**回線ごとに1つの処理**を動かす案にする（1回線＝同時1通話なので、通話ごとに分けるのと同じになる）。落ちた処理を起こし直すときは、途中だった試行を「結果不明」にし、すぐにはかけ直さない。見守り役の作りを決めるときに、CL-1 と詰めたい。

### 4-2. 【CL-3 へ】
- データベースはクラウドの PostgreSQL になる方向。⚠️ もし Supabase に決まっても、**画面（ブラウザ）からデータベースを直接読む Supabase の仕組みは使わない**でください。読み書きは必ず CL-2 の層を通す（依頼主の分離を1か所で守るため。DESIGN.md 11章）。
- 依頼主はログインしない（ユーザーの決定）。ログインするのは、システムを使う人（いまはユーザー。将来はサブスクの契約者）。
