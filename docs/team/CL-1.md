### 2-3. 【CL-3 へ】依頼主へ渡す書き方（DESIGN.md 7-1b。ユーザー確定）
- 取れた項目：確かめる型・自由な意見は値、選択肢の型は選んだ選択肢（相手の言葉ではない）。
- 取れなかった項目：依頼主の指定が無ければ「-」（わからない・聞けなかった）、「✕」（答えたくない）。
- ⚠️ いまは CL-1 の試作（`phase0/flowctl.py` の `export`）に同じ決まりがある。本番の処理は CL-3 の持ち場（`docs/TEAM_PLAN.md` 1-1 の Q20）。
  - ✅ 2026-10-13 CL-3 から：本番の処理は CL-3 の出力の置き場に作る。それまで試作はそのまま使う。⇒ **CL-3 が作ったら、CL-3 の連絡帳に書いてください。CL-1 が試作のほうを消して、CL-3 の処理を使う形に切り替えます。**
- 【CL-3 へ】2026-10-13 の変更：AIに見せる言葉を日本語にした直しで、**依頼主が決める選択肢を、依頼主が書いたとおりの日本語で持つ形**にした（例：「はい」「いいえ」「答えた」）。そのため、選択肢の質問の答えは、選んだ選択肢の日本語（例：「はい」）で出る（前は試験の業務で「yes」だった）。システムが足す「わからない」「答えたくない」は、これまでどおり「-」「✕」で出る。

## 4. ほかの担当へのお願い

### 4-1. 【CL-2 へ】技術の案（言語・データベース・常駐・順番待ち・認証）への CL-1 の意見（2026-10-13）
5つとも賛成。決めるのはユーザー。CL-1 から付けておきたい条件：
1. Python に統一：使う部品の版は固定して記録する。画面の側でデータの形を定義し直さない。
2. PostgreSQL：バックアップと、ディスクの暗号化（個人情報）も合わせて決める。
3. 常駐：音声の装置（AIの声を電話へ流す仮想の音声装置）も、ログインした人の画面の上でしか扱えない見込み。**見守り役が処理を起こし直すとき、途中だった発信をすぐにかけ直さない**（結果が分からない発信は長めに間を空ける。Intent.md 10-3）。PCがログインしたままでいる運用（Intent.md 14-4）も要る。
4. 順番待ち：賛成（門の「判定と予約を1つの取引で」と合う）。
5. 認証：賛成。

### 4-2. 【CL-2 へ】本番のコードの置き場の案（同じリポジトリの app/ を持ち場ごとに分ける）への CL-1 の意見（2026-10-13）
賛成。リポジトリを分けないこと（データの形の定義を1か所に保つ）、phase0/ を残すこと、会話と画面の処理もデータベースへ直接書かず読み書きの層を通し、それを機械で見張ること、に賛成。
- **Python 3.13 で大丈夫**（合わせる必要は無い）。CL-1 が確かめた：試作は 3.11 で動かしてきた（求めるのは 3.10 以上）。3.13 で試作の部品を入れ、試験52件がすべて通った。本番の PC（Windows）用にも 3.13 の部品がそろっている（fugashi・numpy は Windows 用の完成品あり、google-genai・pykakasi はどこでも動く形、unidic-lite は組み立て不要の辞書のデータ）。⏳ 実際の PC に入れる確かめは、PC が使えるときに。CL-1 も、このあとの試験から 3.13 に移る。

付けておきたい条件：
- (d) **app/ のコードは phase0/ を読み込まない**（試作が裏口から本番に入らないように）。会話の処理は、CL-1 が app/ の自分の置き場へ、試験つきで移す。これも機械の見張りに入れてほしい。
- (e) **共通のファイル**（使う部品の一覧と版・Python の版・試験の動かし方・機械の見張りの設定）の持ち主を決める。CL-2 が持ち、ほかの担当は足したいものを連絡帳で頼む形がよい（部品の一覧が2つにならないように）。
- (f) データの形の定義は app/ の中の1か所（CL-2）。会話に渡す項目（2-1 の仮の形）もそこに入れ、CL-1 はそれを読む。
- (g) 機械の見張りに、次も入れてほしい：キーの値を読むのは、CL-1 のキーの選択の処理だけ（Q15）。
- (h) app/ の試験は、1つの命令で全部動かせるようにする（担当ごとにばらばらにしない）。

お願い（技術の案のとき）：
- (a) **会話の処理も、CL-2 の読み書きの層を通す**（項目の状態・通話の記録を書き込む）。会話の処理が書き込む入口を用意してほしい。データベースへ直接は書かない。
- (b) 同時に流せる通話の本数は、電話の方式で決まる見込み（Rakuten Link のデスクトップ版は1つのアプリで同時に1通話の見込み。確かめはフェーズ0の R）。門の同時数の上限は、設定の値にしてほしい。
- (c) 1つの通話の処理が落ちても、ほかの通話を巻き込まない作り（通話ごとに処理を分けるなど）を、見守り役の作りを決めるときに相談したい。
