## 4. ほかの担当へのお願い

### 4-1. 【CL-2 へ】データの形に入れてほしいもの
1. **発信対象の「依頼主の管理番号」と、取込のときの表記**（会社名・電話番号を依頼主のファイルのまま）。依頼主が結果を自分の表と突き合わせる鍵になります（DESIGN.md 7-3-4）。
2. **試行の `dropped` で、「相手が切った」か「回線が切れた」かの区別**（DESIGN.md 9章「回線の切断」に書かれているもの）。通話の終わり方（7-3-3）に使います。
3. **「結果の版」の決まり**：いつ版が上がるか（再判定・検証モードで人が直した・承認した）と、どれが「送ってよい版」か（通話後の検証と判定が済み、検証モードなら人が承認した版）の印。連携の台帳の一意（3-1）と、出力の範囲（7-3-5）に使います（DESIGN.md 15-3 の 10）。
4. **連携の台帳と送り先**（DESIGN.md 4-5）：台帳の行、送り先（依頼主ID・方式・「同じ鍵なら上書き」で受けられるか・認証情報への参照）。
5. **出力の設定の項目**（印の書き方・文字コード・ファイルの形・出す列・出す行の範囲）を、設定の定義に「上書き」の合成の種類で（DESIGN.md 8章）。
6. **項目の値を、型ごとに決まった形で持つこと**（例：日付は年・月・日、時刻は24時間）。書式に直すのは出力の側でします。
7. **読み書きの層（Q14）に「利用者の種類」（運営者／依頼主の利用者）を持てる形**（依頼主のログインを、あとで足せるように。`docs/team/CL-3_DECISIONS.md` の案C）。
8. **門の不許可の理由を、決まった種類（理由の名前）で返すこと**。画面で理由ごとに数え、依頼主に見せる画面では「依頼主をまたいだ間隔」を出し分けるため（DESIGN.md 15-3 の 7）。

### 4-2. 【CL-2 へ】取込で止めてほしいもの
- 選択肢の名前が、出力の印（「-」「✕」、または依頼主が指定した印）と同じもの。依頼主には区別できなくなります（DESIGN.md 15-3 の 6）。

### 4-3. 【CL-1 へ】
- 「会話から返すもの」（`docs/team/CL-1.md` 2-2）の版が上がったら、そこに書いてください。項目の状態の名前は DESIGN.md 4-4 のものだけを使い、画面での言葉は DESIGN.md 7-3-2 で出します。
