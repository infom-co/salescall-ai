# 分担（2026-10-13 ユーザー決定）— CL-1・CL-2・CL-3

クラウドで動くAIを3つにして、SalesCall AI の開発を分ける。この文書は、3つの担当の**全員**が読む。
各担当への引き継ぎ：`docs/HANDOFF_CL-2.md`・`docs/HANDOFF_CL-3.md`（CL-1 は、これまでの担当がそのまま続ける）。

| 名前 | ひとことで | Gemini のキー |
|---|---|---|
| **CL-1 SalesCall AI** | 会話の担当（会話AI・流れの制御・決まった言い方・通話後の検証・フェーズ0の確かめ） | **使うのは CL-1 だけ** |
| **CL-2 SalesCall AI** | 業務の土台の担当（データの形・業務設定と取込・発信対象・安全の門・判定・保存） | 使わない |
| **CL-3 SalesCall AI** | 画面と出力の担当（依頼主別ダッシュボード・検証モードの画面・結果の出力と書き戻し） | 使わない |

## 2. 全員の決まり

1. **報告は日本語で、平易な言葉で書く**（`CLAUDE.md`）。丸数字は使わず (1) (2) と書く。関数名だけで説明しない。
2. **Gemini のキーを使うのは CL-1 だけ**。1つのキーを1回ずつ順番に使う決まりと、利用の上限（会話は1分あたり 65,000 トークン、別の耳は 20,000）があるため。CL-2・CL-3 は、キーが要る確かめが出てきたら、自分で使わず、連絡帳とユーザーに伝える。
3. **持ち場の外を変えない**（1章）。ほかの担当のファイル・章を変えたいときは、ユーザー経由で持ち主へ頼む。
4. **自分のブランチで作業する**。main への取り込みは、ユーザーが確かめてから。
5. **未決定のことを、勝手に決めない**。比べた材料（何が良く、何が悪いか）を添えて、ユーザーに聞く（Intent.md 18章「未確認のことを推測で決めない」）。
6. **対症療法・個別対応をしない。同じ判断は1か所で行う**（一本化）。新しい処理を書く前に、DESIGN.md 2章の表を見る。
7. **データの定義は1か所**。会話に渡す項目の形は CL-1 が決め、それをデータの形にするのは CL-2。CL-3 は CL-2 のデータの形を読み、自分で別に定義しない。
8. **確かめてから「できた」と言う**。試験を書き、通してから報告する（Intent.md 15章「検証していない機能を実装済みと扱わない」）。わざと壊した入力で本当に止まるかも確かめる（Intent.md 16-1）。
9. **キーの値・個人情報を、チャット・ログ・結果のファイル・git に出さない**。`.env` を GitHub に上げない。

## 3. 連絡の仕方（担当どうし）

- 担当どうしは直接話せないので、**連絡帳**（`docs/team/CL-1.md`・`CL-2.md`・`CL-3.md`）を使う。**書くのは自分の連絡帳だけ**、ほかの担当の連絡帳は読むだけ（書き込みがぶつからないように）。
- 連絡帳に書くこと：いまの状態／ほかの担当へのお願い（あて先の名前を付ける）／ほかの担当へ渡すもの（データの形・決まり）とその版／決まるのを待っていること。
- 連絡帳を書き換えたら、ユーザーに「CL-n の連絡帳に、CL-m へのお願いを書いた」と伝える。ユーザーが相手の担当へ知らせる。
- 作業を始めるときは、ほかの担当の連絡帳を main から読み、自分あてのお願いや、受け取るものの変更が無いかを確かめる。
