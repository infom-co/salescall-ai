## 1. 目的

### 1-1. このシステムの目的（Intent.md 1-1）
人が受託している電話業務を、依頼主や業務内容が変わっても同じ基盤のまま、AIが **発信 → 会話 → 回答の取得 → 業務結果の判定 → 保存 → 依頼主への報告** まで、人の手を介さずに **正確に** 代行する。

### 1-2. あなたの目的
**運営者（と、決まれば依頼主）が使う画面と、依頼主へ成果を渡す出力を作ること**です。

- **依頼主別ダッシュボード**：依頼主ごとのタブで画面全体が切り替わり、設定・発信対象・履歴・結果・回線・費用が依頼主ごとに分かれて、**混ざらない**（Intent.md 1-2 の A、5章）。
- **検証モードの画面**：立ち上げ期は、人が発信を承認し、結果を確かめてから依頼主へ送る（Intent.md 原則9、DESIGN.md 10章）。その承認と確認の画面です。
- **結果の出力・書き戻し**：取れた内容と通話の終わり方を、CSV・報告書・外部システムへの書き戻しで渡す。**同じ結果を何度送っても1件になる**（Intent.md 11-3）。
- 「別の依頼主のデータの混入」は、このシステムで**起きた時点で取り消せない害**の1つです（Intent.md 1-3）。画面でも出力でも、0件にします。

## 7. 注意事項

1. **報告は日本語で、平易な言葉で**。関数名や内部の名前だけで説明しない。丸数字は使わず (1) (2) と書く。画面の文言も、平易な日本語で。
2. **新しい処理を書く前に、DESIGN.md 2章の「一本化の表」を見る**。画面の側で、判定・状態・設定の値を計算し直さない（「この業務は完了か」は Q5、「この設定値は結局いくつか」は Q10 が答える。画面は読むだけ）。
3. **依頼主の分離は、画面の切替だけでなくサーバー側で確かめる**（Intent.md 11-2、原則4）。わざと別の依頼主IDで操作して、見えない・変えられないことを試験で確かめる（Intent.md 15章 フェーズ4）。
4. **「わからない」を値で埋めない**（原則10）。画面でも出力でも、「取れた」「取れなかった（-）」「拒否（✕）」「不明」を区別して出す。空欄や0で代用しない。
5. **書き戻しは、同じ結果を何度送っても1件になる形にする**（Intent.md 11-3）。失敗は、通話の状態とは別の「連携の状態」として記録する（DESIGN.md 4-5）。
6. **実測と推定を分けて出す**（利用量・費用。DESIGN.md 12-1）。
7. 画面・ログ・エラーメッセージに、キーの値・不要な個人情報を出さない（Intent.md 12-1）。
8. 試験のデータは**架空のもの**だけを使う。
9. 決まっていないことは、比べた材料（何が良く、何が悪いか）を添えてユーザーに聞く。
10. 自分のブランチで作業し、main への取り込みはユーザーが確かめてから。
11. 1つ終えるたびに：試験を通す → 自分の章と連絡帳を書き換える → ユーザーに報告する。

## 8. やってはいけないこと

- ⛔ **Gemini のキーを使わない**（使うのは CL-1 だけ）。
- ⛔ **言語・画面の作り方が決まる前に、本番のコードを書き始めない**。
- ⛔ **データの形を自分で定義しない**（CL-2 のものを読む）。足りなければ CL-2 へのお願いとして書く。
- ⛔ 画面や出力から、依頼主IDを受け取る層を通らずにデータを読み書きしない。
- ⛔ 画面の側で、判定・状態・設定の値を計算し直さない（二重化しない）。
- ⛔ `phase0/`（CL-1 の試作と確かめ）、CL-2 のコードを変えない。
- ⛔ 持ち場の外の文書の章（3-4・`docs/TEAM_PLAN.md` 1-3）を書き換えない。DESIGN.md 7-1b の「渡す内容」（ユーザー確定）を変えない。
- ⛔ 実在の顧客の情報・キーの値・個人情報を、チャット・ログ・結果のファイル・git に出さない。`.env` を GitHub に上げない。
- ⛔ main へ直接送らない。

## 9. 合格の条件（Intent.md 15章・17章から）

- **フェーズ4（依頼主別ダッシュボード）**：依頼主を切り替えると、対象のデータが正しく変わり、**別の依頼主の情報を表示・更新できない**（わざと別の依頼主IDで操作して確かめる）。
- **フェーズ7（結果出力・外部連携）**：正しく出力でき、失敗しても再処理と原因確認ができる。**同じ結果を何度送っても1件になる**。
- 出力の書き方（Q20）：取れなかった項目は、依頼主の指定が無ければ「-」（わからない）・「✕」（拒否）で書く（DESIGN.md 7-1b）。選択肢の型は、相手の言葉ではなく選んだ選択肢を書く。
