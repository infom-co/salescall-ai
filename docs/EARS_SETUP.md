# 別の耳を試すための設定（コピペするだけ）

会話のAIとは別の音声認識（別の耳）を3つ試します（DESIGN.md 6-10 の (5)・PHASE0_VERIFICATION.md G-15）。
2026-10-17 ユーザー：「3つの耳の準備はコピペするだけの状態にしてください」。

| 耳 | ユーザーの設定 |
|---|---|
| ReazonSpeech（PC の中で動く） | **要りません**（いまの設定のまま、モデルを取って動かせました） |
| AmiVoice | 下の (1) と (2) |
| Soniox | 下の (1) と (2) |

設定が終わったら、(3) の一文をこの会話に送ってください。そのあとは、こちらで1つの命令（`python phase0/ears_try.py`）を流して、足りないものの確かめ → 1本だけつないで確かめ → 全部の声で測る → 比べた表、まで進めます。

⚠️ キーは、チャットには貼らないでください（作業環境の設定の欄にだけ入れます）。

---

## (1) 通信の許可（接続先を足す）

1. この会話の画面の上にある、クラウド環境の名前を押して、「編集」を開きます。
2. 「ネットワークアクセス」で「制限付き」を選びます（画面によっては「カスタム」）。
3. 「許可するドメイン」の欄に、下の枠の中を**全部**貼ります（1行に1つ）。
4. 「パッケージ管理を許可する」（画面によっては「よく使うパッケージ管理の一覧も含める」）のチェックは、**付けたまま**にします。
5. 保存します。

画面の表示が英語のときの名前：ネットワークアクセス＝`Network access`・制限付き＝`Limited`（または `Custom`）・許可するドメイン＝`Allowed domains`・パッケージ管理を許可する＝`Allow package managers`（または `Also include default list of common package managers`）。

```
acp-api.amivoice.com
stt-rt.soniox.com
api.soniox.com
*.googleapis.com
github.com
*.githubusercontent.com
```

- 上の3行が、今回足す接続先です（AmiVoice・Soniox）。
- 下の3行は、いま使えているもの（会話のAIの Gemini と、PC の中の耳のモデルの置き場）です。ネットワークの設定を切り替えたときに止まらないよう、念のため一緒に入れます。
- 手順の公式の説明：https://code.claude.com/docs/en/cloud-environments#network-access

## (2) キーを取って、環境変数の欄に入れる

### AmiVoice のキー
1. https://acp.amivoice.com/ でアカウントを作ります。
2. ログインして「マイページ」の「プラン申込」から申し込みます。⚠️ 公開されている説明では、毎月60分までの無料分を使うときも、クレジットカードの登録が要るとされています（2026-10-17 ユーザー：ログインはできたが、APIキーが取れなかった）。
3. 申し込みが済んだら、「マイページ」の「APIキー」をコピーします。
- 試験で流す音声は、1回で30分ほど（1言の答えの165本で約10分・通話の中の試験の153本で約13分。2026-10-17 の ReazonSpeech の実測）＝毎月60分の無料分に収まる見込みです（記録を残さない接続先にも無料分が当たるかは、公式の説明でまだ確かめていません）。

### Soniox のキー
1. https://console.soniox.com/ でアカウントを作ります。
2. 「プロジェクト」の中の「APIキー」で新しいキーを作り、コピーします。
3. ⚠️ 残高（前払いのお金）を入れます。2026-10-17：キーもつなぎ方も通ったが、Soniox が「残高がありません（402：Organization balance exhausted）」と返して、文字にする前で止まった（作ったばかりのアカウントには、無料の残高が付いていなかった）。
- 試験で流す音声は、1回で30分ほど＝料金の目安は約0.06ドル（10円ほど。リアルタイムで1時間あたり約0.12ドル＝Soniox の比較ページの値。公式の料金表ではまだ確かめていません）。

### 入れる場所
(1) と同じ「編集」の画面の「**環境変数**」の欄です（前に `GEMINI_API_KEY_1` などを入れた欄。画面の表示が英語のときは `Environment variables`）。
下の2行を貼り、「ここに…」の部分を、それぞれのキーに置き換えて保存します。

```
AMIVOICE_APPKEY=ここにAmiVoiceのAPIキー
SONIOX_API_KEY=ここにSonioxのAPIキー
```

- 「ネットワークのシークレット」（`Network secrets`）の欄ではなく、「環境変数」の欄です（この2つの会社は、つないだあとの最初の知らせの中でキーを送る形なので、中継所がキーを付ける形が使えません）。
- 片方だけでも試せます（入れたほうの耳だけを測ります）。

## (3) 終わったら、この一文を送る

```
耳の設定をしました。試験を流してください
```

- 設定が、この会話の作業環境に届くまで、少し時間がかかることがあります。届いていなければ、こちらの確かめで分かるので、そのときにお伝えします。

## こちらで流すもの（CL-1 用）
- `python phase0/ears_try.py --check`：足りないものの確かめだけ（キーがあるか・接続先に届くか・モデルがあるか）。
- `python phase0/ears_try.py`：4つの耳（Gemini の書き起こしの耳＝物差し・AmiVoice・Soniox・ReazonSpeech）を、同じ測り方で順に測って比べる。結果は `phase0/results/EARS-TRY_*.json`。
- 接続先の名前とキーの名前は、コードの `ears.py`・`ears_try.py` と、この文書の枠の中とで同じでなければならない（`test_offline.EarsTryTest` が見張る）。
