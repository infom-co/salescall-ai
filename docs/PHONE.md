## 1. 電話の部品が受け持つこと・受け持たないこと
| 受け持つ（PC の上で） | 受け持たない（サーバーの1か所が決める） |
|---|---|
| かける・切る・通話中か・テスト番号を鳴らして答える・おわびの録音を流して切る（形は `link.phone.Phone`） | かけてよいか（門）・いつ・どこへかけるか・番号のせいか回線のせいか・行をどう終えるか |
| お客様の声をサーバーへ送る・サーバーから届いた声を通話へ流す・声の形を変える（1か所） | 何を話すか・いつ話すか（会話＝CL-1） |
| 電話の出来事（呼び出し・応答・切れた・電話網のお知らせの声）をサーバーへ知らせる | 出来事から試行をどう終えるか（`core/attempts`） |
| ショートメールを1通送り、送れたかを返す（知らせの送り方の1つ） | 何を・だれへ・いつ送るか・送り直し（`output/notices`） |

- 判断を PC に持たない（PC は読まれる前提＝DESIGN.md 5-5）。分からないときは、いつも「かけない側」「通話中とみなす側」に倒す。
- 方式（Rakuten Link・ハンズフリー・電話API）ごとに部品を1つ作り、どれも同じ形（`Phone`）にする。最初は Rakuten Link デスクトップ版（フェーズ0 R-1 合格：スマホと PC が同じ光回線の Wi-Fi にいれば、PC から発信できた＝2026-10-12 管理者が確かめた）。置き場は `app/src/salescall/agent/phones/rakuten_link/`（分担の表の `agent/phones/`）。

## 2. Rakuten Link の部品の作り
### 2-1. 画面の操作（かける・切る・通話の状態）
- Windows の画面の部品を、プログラムから読む・押す仕組み（UI Automation。Python の部品 pywinauto の UIA）で操作する。マウスの位置や画面の絵では操作しない（画面の大きさ・明るさで壊れるため）。
- 画面の部品の見分け方（名前・種類）は、部品の中の1つの表（`screen.py` の `SCREEN`）にだけ持つ。Rakuten Link の版が上がって見分けられなくなったら、表だけを直す。見分けられないときは、かけない（`CallNotPlaced`＝お客様の電話は鳴っていないと言える）・通話中か分からない（`in_call` は真＝かけない側）にして、修正依頼が出る形にする（電話の部品の誤りとして知らせる）。
- 画面の操作は、回線（スマホ1台＝Rakuten Link 1つ）ごとに1つの流れで、順に1つずつ。どの操作にも期限を付ける（期限は `link.protocol.ANSWER_BY` の内側）。
- Rakuten Link は1つずつしか流せない（計画書 8-3：1回線で同時に1本）。PC 1台で回線を2本以上使うには、Rakuten Link を2つ動かせるかを確かめる必要がある（⏳ R-8。できなければ、回線ごとに PC を分ける）。

### 2-2. 声の受け渡し
- 仮想の音声装置を2本使う。**おすすめ：Virtual Audio Cable（作者 Eugene Muzychenko。Business の決まり＝仕事で使ってよい・50ドル・買い切り）**（2026-11-20 に調べた。管理者に案内した）：
  - 選んだ理由：(1) 仕事で使ってよいことが決まりに書いてある（Business）。VB-Audio の VB-CABLE A+B は寄付の形で、仕事で使う決まりがはっきりしない (2) 版が今も出ている（4.71＝2026-06） (3) 本数を設定で増やせる（回線を足すとき） (4) VB-CABLE は Windows の更新のあとに使えなくなった報告がある（入れ直しで直った）。
  - ✅ 2026-11-20 管理者「買うまでは音量で調整」（確かめのあいだは試しの版のまま。モニターの音量で調整する。⚠️ 知らせの声は電話の相手と AI へ渡る声にも混ざるので、本物のお客様にかける前に必ず Business に入れ替える）。
  - 試しの版は、本物と同じに動くが、女性の声の「試しの版」の知らせが混ざる。⇒ 自分たちの携帯での確かめ（R-2〜R-9）は試しの版でよい。**お客様にかける前に、必ず Business を買って入れ替える**（知らせの声がお客様に届くため）。
  - A：Rakuten Link の「スピーカー」を A にする → 部品が A から録る（お客様の声）。
  - B：部品が B へ流す（AI の声・録音）→ Rakuten Link の「マイク」を B にする。
  - 2本に分けるので、AI の声が部品の録る側へ戻らない（PC の中の折り返しが無い）。電話の向こうからの折り返し（エコー）は R-4 で測る。
- 声の形を変えるのは、部品の中の1か所（`audio.py`）だけ（計画書 8-3「変換の処理を1か所だけ置く」）：
  - サーバーへ送る形：16kHz・16bit・1ch・20ms ごと（会話AIの入力の形＝`phase0/common.INPUT_RATE`。⏳ CL-1 と合わせる）。
  - サーバーから受ける形：⏳ CL-1 と決める（案：24kHz・16bit・1ch。会話AIの出力の形のまま送り、部品が装置の形へ変える）。
  - 装置の形（48kHz など）との行き来は、部品の中で変える。
- 声を流す口（`play`）は待たずに返す（流す順番待ちを部品の中に持ち、PC の部品のやり取りを止めない）。
- **【2026-11-20 CL-1 の連絡帳 4-226 の (2)・4-227 の (1) を受けて決めた形】** どちらも決めるのはサーバー（会話の流れの制御・見張り `offscript.SpeechGate`）。電話の部品は言われたとおりに動き、起きたことを知らせるだけ：
  - (1) **流し終えた知らせ**：サーバーから届いた声のひと続き（頼みの印つき）を、装置へ流し終えた時刻を、出来事としてサーバーへ返す（例 `{"kind": "played", "ref": 頼みの印}`）。黙ったときの見張りの秒 `silence_s`・待つ上限の秒 `hold_wait_s` の数え始めは「その返事の声が終わってから」なので、送り終えた時刻ではなく、通話へ流し終えた時刻が要る（PC の順番待ちの中に残っている間は、まだ終わっていない）。
  - (2) **流すのをやめる口**：サーバーが「やめて」と言ったら、順番待ちに残っている声を捨て、流している途中の声も止める（`stop_playing`）。外れた言葉を止める見張り（`stop=True`）が働いたとき・お客様が話し始めたときに使う。止めた声は (1) の「流し終えた」ではなく「止めた」と返す（どこまで流れたかの秒を添える＝お客様にどこまで聞こえたかの記録）。言い直しのターンの見張り（`stop=False`）はサーバーが知らせるだけで、PC には何も頼まない。
  - **【2026-11-21 電話の部品の側は作った】** `RakutenLink.play(pcm, ref=None)`（印があれば流し終えたとき `{"kind": "played", "ref"}`）・`stop_playing()`（止めた声ごとに `{"kind": "stopped", "ref", "played_s"}`。まだ流れ始めていない声は 0 秒）。装置の順番待ち（`sound_vac`）が、ひと続きごとに流し終えたことと、止めたときに流れた秒を返す。電話を切ったら印は捨てる。✅ やり取りの形（声のひと続きに印を付けて送る・「やめて」の頼み・2つの出来事）は、やり取りの版 9 で入った（CL-2 の 4-469。PC の部品の土台が `phone.play(audio, ref=…)`・`phone.stop_playing()` を呼ぶ）。

### 2-3. 通話の状態の読み取り（R-6）
- 「呼び出し中・つながった・切れた」は、画面の表示（通話の時間の表示・切るボタンがあるか）を正にし、声で補う。
- 声で読むもの（`tones.py` の1か所）：
  - 呼び出しの音（日本の標準：400Hz を 1秒鳴らして 2秒休む）＝お客様の電話が鳴っている。
  - 話し中の音（400Hz を 0.5秒ずつ鳴らして休む）。
  - 電話網のお知らせの声（`link.phone.NOTICES`：電源が切れている・電波の届かない所・使われていない）：管理者の PC で録った見本と比べて見分ける。見分けられなければ None（決めつけない）。
  - ⚠️ Rakuten のネットワークの音・声が標準と同じかは分からない。R-6 で本物を録って、見本と数字（周波数・長さ）を決める（推し量って決めない）。
- 出来事は `on_event` の口で、そのまま知らせる（形は CL-1・CL-2 と決める。いまの決まり：お知らせの声は `{"kind": "notice", "notice": 種類}`）。

### 2-4. テスト番号を鳴らす（`test_ring`）
- テスト番号へかけ、`ANSWER_BY` のうちに：呼び出しの音・話し中の音・お知らせの声のどれかが返った＝真（回線から発信できた）、どれも無いまま終わった・アプリが発信できない＝偽、見分けられない＝None。相手が出る前に切る。
- 話している途中なら試さない（PC の部品の土台が断る）。
- **お知らせの声を聞き分けられるまでの形**（2026-11-20 の計画書 8-2 の読み直しで直した。前は「何も聞こえないまま終わった」も None と答えていて、計画書の「発信できない」と合っていなかった）：何も聞こえないまま電話が終わった＝偽。何かの声は聞こえたが呼び出しの音・話し中の音ではないまま終わった＝None（電源オフ・圏外のお知らせの声なら「発信できた」なので、聞き分けられないうちは「発信できない」と決めつけない）。⏳ お知らせの声の聞き分けは、見本を録ってから（R-6）。
- 通話の途中に次の発信を頼まれたら、かけずに断る（計画書 8-3「1回線で同時に1本」。話している電話を保留にしない）。

### 2-8. 折り返しの着信（計画書 8-7。⏳ まだ決まっていない＝計画書 18章）
- お客様が表示された番号へ折り返してきたときの扱いは、まだ決まっていない。決まるまで、電話の部品は着信に**出ない**（勝手に出て、AI のいない電話で無言にしない）。
- ⏳ 着信が鳴っているあいだの画面の状態を、通話の状態の読み取り（2-3）が「かけている」「通話中」と取り違えないかを、R-6 の続きで確かめる（取り違えると、着信のあいだ次の発信を止めるだけ＝かけない側なので害は無いが、記録が誤る）。扱い方が決まったら、管理者に伺ってから作る。

### 2-5. おわびの録音を流して切る（`play_apology_and_hang_up`）
- 録音（共通の一言 `line_trouble_ask`・`line_trouble_bye`。声の型ごと）は、通話の前に PC に持っておく（サーバーとのつながりが切れたときにも流すため）。✅ PC の側の置き場は作った（2026-11-22・`agent/phones/apology_cache.py`：届いた WAV を指紋と照らしてからしまう・声の型ごとに2つ・読むときに装置の形へ変えるのは `audio.resample` の1か所・どちらか無ければ None＝すぐ切る）。⏳ サーバーから配るやり取りの形は CL-2 の持ち物＝案を連絡帳 4-1c の 74 に出した（PC が持っている指紋を hello で知らせ、サーバーが違うものだけ送る）。
- 流し方は `Phone.play_apology_and_hang_up` の決まりのまま（ひとつ目 → お客様の返事を待つ → ふたつ目 → 切る。`APOLOGY_WAIT` のうちに）。

### 2-5b. 通話の録音を消す（通話の録音の置き場を作るとき＝⏳ フェーズ1。CL-1 の 4-252・CL-2 の 4-476 の (1)）
- Fly.io に置いた通話の録音を消す処理は、(1) 残す日数を過ぎた録音と、(2) 日数を待たずに消してよい通話（業務の設定 `recording.save` が「残さない」で、その週の誤判定率の抜き取りが済み、選ばれなかった通話＝core の `recordings.unsaved_done(tx)` の1か所）の録音を消す。
- 消さない通話（`salescall.recordings_held`＝正解が付く前の抜き取り・検証モード・まだ決まっていない決定の通話）は消さない。どちらの決め方も写さず、core の1か所を読む（同じ決まりを2か所に持たない）。

### 2-6. スマホとの連携の見張り
- Rakuten Link デスクトップ版は、スマホと同じ Wi-Fi にいないと発信できない（R-1）。スマホの電源・スリープ・Wi-Fi の切断で、その回線は使えなくなる。
- 部品は、画面の「連携していない」表示を読み、その回線を「使えない」として知らせる（かけない）。✅ 知らせ方は、やり取りの版 8 で入った（動いている合図の回線の一覧に、電話の部品が「使える」と答えた回線だけを入れる＝下の「いま使えるか」）。使えないことが続いたら、契約者と管理者に知らせる（見守り役の決まりのまま）。

### 2-7. ショートメール（知らせを送る）
- ✅ 2026-11-18 管理者：知らせは Rakuten Link のショートメールが最優先、使えなければチャットワーク。
- サーバーの知らせの部品（`output/notices`）が文と宛先を決め、PC の部品へ「この1通を送って」と頼む。部品は Rakuten Link のメッセージの画面を操作して送り、送れたか（画面に送信済みが出たか）を返す。送れたか分からなければ「送れなかった」として、サーバーが決まりどおりチャットワークへ回す（二重に届くより、届かないほうを避ける。R-9 で、送ってご家族に届いたことを確かめた＝下の 3章）。
- **知らせの送り先の番号は、前もって Rakuten Link の連絡先に登録しておく**（2026-11-20 管理者が教えてくれた：登録されていない番号は「連絡先に登録」を押さないと宛先にならない）。プログラムはスマホの連絡先を書き換えない。登録されていなければ送らずに `NotRegistered` で答え、サーバーはチャットワークへ回して「知らせの送り先を、Rakuten Link の連絡先に登録してください」と画面に出す（⏳ 頼みの答えの形は CL-2 へのお願い 58 の (2)(a) と一緒に）。候補が2つ以上出たら、違う方へ送らないよう送らない。
- 通話の途中は、同じ回線のスマホでショートメールを送ってよいかを R-9 で確かめる（送れなければ、通話の合間に送る）。
- **【2026-11-21 形がそろった（やり取りの版 8＝CL-2 の 4-459）】** 頼みは `send_sms`（欄 phone・national・text）。電話の部品は `send_sms(phone_e164, text, *, national)`：宛先の欄へは national をそのまま入れる（部品の中で番号の形を変えない）・通話の途中は送らない（CallWithheld）・連携していない／宛先が連絡先に無い＝CallNotPlaced・ほかの誤り＝送れたか分からない。かける `start_call(…, *, national)`・テスト番号 `test_ring(…, *, national)` も同じ（番号の欄は national）。
- **どの回線から送るか**は、知らせの部品の1か所（`output/notices.SmsTransport`）：その契約者の、いま PC とつながっている回線から順に試し、送らなかった・送れなかったと確かに言えるときだけ次の回線へ。送れたか分からないときは重ねて送らず「送れなかった」（チャットワークへ回る）。管理者あては、管理者自身の契約者の回線（見守り役の設定 admin_tenant）。✅ 見守り役の仕事が PC とのつながり（links）と回線の持ち主（sms_owner）を渡す形は main に入った（CL-2 の 4-469・`supervisor/jobs.notices`・`admin_notices`）。
- **いま使えるか**（`usable`）：土台が1秒ごとに聞くので、状態を読む流れのついでに覚えた答え（3秒まで）を返す（画面を毎回は読まない）。ショートメールを送る直前は、覚えでなく画面を読む。

## 3. 確かめの手順（管理者の PC で。フェーズ0 の R を、この作りで行う）

**結果（2026-11-20・管理者の PC。道具 `probe_audio.py`。Windows 11 26100・Python 3.14.2）**
- 装置：Line 1・Line 2（Virtual Audio Cable の試しの版）を見つけた。
- R-2：△ 相手側の音が 0.8秒・大きさ十分（二乗平均の平方根の最大 5546）＝**Rakuten Link の声は Line 1 に届く**。途切れずに録れるか（20秒）は未確認。
